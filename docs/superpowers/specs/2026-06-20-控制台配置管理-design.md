# 围观象棋 · 本地控制台(配置管理)设计

- 日期:2026-06-20
- 状态:已与用户确认设计,待写实现计划
- 一句话:在现有 Web 应用内新增本机控制台 `#/console`,集中**展示并即时编辑**所有必要配置——角色人设/音色、API key 与模型端点、运行参数(聊天/导演/诊断)、跨会话记忆,以及对局/消息浏览管理。

## 目标与范围

**目标**:把目前散落在代码常量与 `.env` 里的配置,收敛到一个"代码默认值 ⊕ 数据库覆盖"的运行时配置层,并提供一个本机控制台增删改查。改动**即时生效**(LLM 凭据经热重载),无需改代码、多数无需重启。

**用户已确认的关键决策**
1. 持久化:**设置库覆盖 + 即时生效**(含 key 改动热重载 LLM 客户端);`.env` 仅作"库无值时"的首次引导。
2. "日志"= **对局/消息历史浏览**(复用现有表)。**不做**服务端运行日志流、配置变更审计、LLM/TTS/引擎调用记录。
3. 访问控制:**无**(服务仅监听 127.0.0.1,单人本地);key 页面默认脱敏、点击才显示。

**不在范围(YAGNI,已确认排除)**:服务端 pino 日志实时流;配置变更审计表;LLM/TTS/引擎调用计量表;登录/鉴权/多用户;远程访问。

## 现状(为何需要这层)

- **角色**:硬编码在 `server/src/personas/personas.ts` 的 `PERSONAS`;音色映射 `voiceForPersona` 硬编码在 `server/src/voice/dashscope-tts.ts`。
- **密钥/模型**:`server/.env` → `process.env`,仅启动时读一次(`DashscopeLLM` 构造、`/tts` 路由、TTS 端点/模型)。
- **运行参数**:散落常量——`ws-server.ts` 的 `tempo {minSilenceMs:4000, maxPerMin:12}`、idle `Math.random()<0.35` / `20_000ms`;`speaker-select.ts` 的 `SPEAK_THRESHOLD=0.6`、jitter 宽 `0.4`;`chat-engine.ts` plan() 内 `reactProb 0.3`、长度档阈值 `0.5/0.85`;`game-session.ts` 的 `MULTIPV`、`movetime:500`;导演 `maxDropCp/targetBand/strength`(由 `game-session.buildContext` 按 mode 给);诊断 `depth:12`。
- **记忆**:由独立的「记忆重构」子项目(SurrealDB 语义记忆)交付的异步 **`MemoryStore`** 接口提供;控制台"记忆"页**仅依赖该接口**(`list/update/remove`),不直接碰底层存储。详见 [2026-06-20-记忆重构-SurrealDB语义记忆-design.md](2026-06-20-记忆重构-SurrealDB语义记忆-design.md)。
- **对局/消息**:`games/moves/messages` 表已在,缺统一浏览与级联删除。

## 架构

### 1. RuntimeConfig 服务(核心)
`server/src/config/runtime-config.ts`:**代码默认值 ⊕ 数据库覆盖**的唯一读取入口。
- 默认值集中到 `server/src/config/defaults.ts`(从上述现状常量提取)。
- 读:`getChat()/getDirectorDefaults()/getEngineParams()/getDiagnose()/getLlm()/getTts()/personas()/voiceForPersona(id)`,每次返回"默认 ⊕ 库覆盖"的合并结果(无缓存或带版本号失效,保证即时)。
- 写:`updateSection(section, patch)` 校验后写 `app_settings`;`updatePersona(id, patch)` / `resetPersona(id)` 写/清 `persona_config`。
- LLM 变更钩子:`updateSection('llm'|'tts', …)` 触发 `onLlmChange()`(见 MutableLLM)。
- 消费端改为从本服务读取,不再直接 import 常量。

### 2. MutableLLM 热重载包装器
`server/src/llm/mutable-llm.ts`:实现 `LLMProvider`,持有可替换的内层 provider。`ChatEngine`/`reflect` 持有这个包装器;改 LLM 配置时 `rebuild(cfg.getLlm())` 重建内层(`DashscopeLLM` 或缺 key 时 `FakeLLM`),上层无感、无需重启。

### 3. 数据模型(新增 2 表,其余复用)
```sql
CREATE TABLE IF NOT EXISTS app_settings (
  section    TEXT PRIMARY KEY,   -- chat | director | engine | diagnose | llm | tts
  json       TEXT NOT NULL,      -- 该段的覆盖(部分字段)JSON
  updated_at TEXT NOT NULL
);
CREATE TABLE IF NOT EXISTS persona_config (
  id          TEXT PRIMARY KEY,  -- player | laopaoer | coach | netizen
  name        TEXT NOT NULL,
  is_player   INTEGER NOT NULL,
  skill       TEXT NOT NULL,     -- strong | medium | weak
  background  TEXT NOT NULL,
  voice_style TEXT NOT NULL,     -- 口吻脾气
  leaning     TEXT NOT NULL,     -- 帮踩倾向
  tts_voice   TEXT NOT NULL,     -- qwen3-tts-flash 音色 id
  enabled     INTEGER NOT NULL DEFAULT 1,
  updated_at  TEXT NOT NULL
);
```
- 首次启动:若 `persona_config` 为空,用代码 `PERSONAS` + 默认 `voiceForPersona` 播种。
- key 存于 `app_settings('llm')` 的 json(本地 SQLite,信任级别同 `.env`);库无 llm.apiKey 时回退 `process.env.DASHSCOPE_API_KEY`。

### 4. 配置段字段与默认值
- **chat**:`minSilenceMs(4000)`、`maxPerMin(12)`、`speakThreshold(0.6)`、`jitterWidth(0.4)`、`idleProb(0.35)`、`idleIntervalMs(20000)`、`reactProb(0.3)`、`lenShortP(0.5)`、`lenLongP(0.15)`。
- **director**:按 mode(coach/humanlike)的 `maxDropCp`、`targetBand{low,high}`、`strength`(默认从 `game-session.buildContext` 提取)。
- **engine**:`pikafishPath`(展示,改后需重启)、`multipv`、`movetime(500)`(按次,即时)。
- **diagnose**:`depth(12)`。
- **llm**:`apiKey`、`model('qwen-plus')`、`baseURL`。
- **tts**:`endpoint`、`model('qwen3-tts-flash')`。(逐角色音色在 `persona_config.tts_voice`。)

### 5. Admin HTTP 路由(均仅 127.0.0.1,无鉴权)
- `GET /admin/config` → 各段 + personas(**key 脱敏** `sk-****1Xqy`)。
- `GET /admin/config/llm/reveal` → 返回完整 key(本机)。
- `PUT /admin/config/:section` → 校验并更新一段;`llm/tts` 段触发热重载。
- `GET /admin/personas` · `PUT /admin/personas/:id` · `POST /admin/personas/:id/reset`(恢复默认)。
- `GET /admin/memory?personaId=&kind=`(→ `MemoryStore.list`)· `PUT /admin/memory/:id`(→ `update`)· `DELETE /admin/memory/:id`(→ `remove`)。**经 `MemoryStore` 接口而非直接 SQL**;`id` 为字符串(SurrealDB record id)。手动新增记忆(`POST`)依赖语义写入路径(embed + judge),YAGNI 排除——记忆主要由反思自动产出,控制台只做查/改/删。
- `GET /admin/games`(列表)· `GET /admin/games/:id`(复用 moves+messages)· `DELETE /admin/games/:id`(级联删 moves/messages/move_annotations/drill_attempts/growth_metrics)。

### 6. 前端控制台
- 路由:现有 hash 路由新增 `#/console`;`main.tsx` 顶部导航加入口。
- 页面 `web/src/pages/ConsolePage.tsx`:子标签 **角色 | 密钥与模型 | 运行参数 | 记忆 | 对局与消息**;复用 `PageShell` 暗色风、`ErrorBanner`。
- API 客户端 `web/src/api/admin.ts`。
- 表单:保存→PUT→提示成功/失败;key 默认脱敏 + "显示"切换(调 reveal);数值参数带范围与说明;角色音色用下拉(已验证可用:Dylan北京话/Ethan/Serena/Eric/Cherry/Chelsie/Kiki/Rocky/Jada沪/Sunny川)。

## 即时生效矩阵
- **即时(下一次刺激/请求读新值)**:角色人设/音色、聊天参数、导演参数、诊断 depth、TTS 端点/模型、movetime/multipv。
- **热重载即时(无需重启)**:LLM key/model/baseURL(经 MutableLLM 重建)。
- **需重启**:仅 Pikafish 引擎可执行路径(进程启动时 spawn);页面标注。
- **写库即时**:记忆改/删(经 `MemoryStore`)、对局删除。

## 消费端改造清单(实现计划据此分解)
- `personas.ts`:`PERSONAS` 降级为"默认/播种源";`spectators()/getPersona()` 改为从 `RuntimeConfig.personas()` 读(或由 cfg 统一提供)。
- `dashscope-tts.ts`:`voiceForPersona` 默认映射保留为回退;实际取 `persona_config.tts_voice`。
- `speaker-select.ts`:`pickSpeakers` 接受 `threshold/jitterWidth` 参数(由 cfg 传入),移除模块常量。
- `chat-engine.ts`:`tempo`、`reactProb`、长度档阈值、idle 相关从 cfg 读;持有 MutableLLM。
- `ws-server.ts`:tempo / idle 概率与间隔 / 导演 / 引擎 analyze opts / 诊断 depth 从 cfg;构建 MutableLLM;`/tts` 读 `cfg.getTts()` 与 cfg 音色;挂载 admin 路由。
- `game-session.ts`:`buildContext` 的导演参数、`movetime/multipv` 从 cfg。
- 记忆:**不在本子项目改**——`update/remove/list` 由「记忆重构」子项目在 `MemoryStore` 接口上提供;控制台 admin 路由直接调注入的 `MemoryStore` 实例。
- `games-repo.ts`:补 `deleteGame(id)`(级联)。

## 风险与权衡
- **改造面**:多模块从"import 常量"改为"读 cfg",是主要工作量;通过 RuntimeConfig 单一入口与逐模块小改控制风险,每步验证。
- **key 落库**:明文存本地 SQLite,与 `.env` 同信任级别;仅 127.0.0.1、页面脱敏;不入库到 git(SQLite 已 gitignore)。
- **即时生效语义**:对"局中"参数(如导演 maxDropCp),即时=下一手读新值,不回溯已走的棋——符合预期。
