# 围观象棋 · 茶馆讨论重做(贴棋局 + 老黑参与 + 自然密度)设计

- 日期:2026-06-21
- 状态:已与用户确认设计,待写实现计划
- 一句话:让旁观者讨论**始终贴当前这盘棋**(可带扣着局面的棋识,不扯场外),让 **AI 棋手老黑完整参与**讨论,讨论**密度事件驱动、有起有伏、你来我往**;同时把上一次"过度收短"收回为"短而有料"。

## 背景(为什么重做)

用户反馈三点:① 旁观者"说的都是无关痛痒的,没有聊的欲望"——讨论脱离棋局;② AI 棋手老黑"也要参与进来";③ 讨论密度要"最自然的设计"。

诊断现状(`server/src/chat/chat-engine.ts` + `server/src/ws-server.ts`):
- **话题由刺激类型决定**。走子(人/AI)刺激带 `moveZh`+局势 → 评这步棋(贴局面)。但 **idle 刺激**(ws-server 每 20s、35% 的机械定时器)提示是"随口扯点棋外的(你自己的行当/家里/最近遇上的事)"——**两步棋之间只有 idle 在发,全是场外闲篇 → "无关痛痒"**。
- **老黑(persona `player`,isPlayer:true,人类的对手)** 只在 `stim.byPlayerPersona`(它自己刚走完一步)时以 40% 自评一句;`pickSpeakers` 只在非 player 里选,所以老黑**从不参与**旁观者讨论或点评人类的棋 → "不在场"。
- 密度:`TempoGuard`(最短 4s/每分钟 12 上限)+ `pickSpeakers` 固定 ≤2 人 + 每 20s 机械 idle → 不跟棋局起伏走、机械感。
- (附:上一改动把 `maxTokens` 砍到 50 并删了"把道理说透",已在本设计收回。)

## 用户已确认的关键决策

1. **相关性**:讨论**始终贴当前棋局**;可以"讲出与局面相关的象棋知识(历史故事、残局、棋界等)",但必须**扣着眼前局面**,不是随机场外闲篇。
2. **老黑参与**:**完整参与**——自评己方走法 + 接旁观者的话/被点名回怼 + 偶尔点评人类的棋或局面,用他"沉稳、闷、偶尔得意"的脾气,带"这是我的对局"的立场。
3. **密度**:**事件驱动、有起有伏 + 你来我往**——有看头的棋步→几人短促交锋(含老黑),平淡时少说/不说,长考时偶尔一句;去掉每 20s 机械触发。

## 架构(改造点,均在 chat-engine / speaker-select / ws-server / defaults)

### 1. 相关性:讨论贴棋局 + 扣局面的棋识
- **系统 prompt** 重写"闲篇"口子:从"也会扯句闲篇"改为"主要谈眼前这盘棋——这步好坏/为什么/对方该怎么应/威胁/棋理;**可自然带一句扣着当前局面的棋识(残局理论、历史掌故、棋谚、棋界轶事),但要跟眼前局面挂钩,宁可不带也别瞎编**;别通篇贫嘴"。**恢复"把道理说透"** 的讲棋理实质(与简短平衡)。
- **idle 分支重写**:不再"扯棋外/行当/家里"。改为就着当前局面说(僵着/谁占优/红方该怎么走/黑炮那步还没应/催走子),**可带一句扣着局面的棋识**。为让 idle 知道"当前局面",chat-engine 给每局缓存**最近一次走子刺激的上下文** `lastCtx: Map<gameId, {moveZh, qual, ply}>`(在每个带 `moveZh` 的刺激处更新);idle 的 prompt 用这份上下文 + `contextLine`(最近聊天)续聊。

### 2. 老黑(AI 棋手)完整参与
- `onStimulus` 选完旁观者 speaker 后,决定老黑是否加入:
  - `byPlayerPersona`(老黑自己刚走)→ 以较高概率(0.6)push `player` 自评(原 0.4 提升)。
  - 其余刺激(人类走子 / move / 较有看头的 idle)→ 以中等概率(0.3)push `player` 作为**参与者**(接话/点评人类的棋/局面),让老黑在场。
  - 控制总人数与节奏,避免老黑刷屏。
- `plan()` 新增"老黑作为参与者"分支(区别于自评):提示带身份与立场——"你是正在下这盘的老黑,沉稳、闷、偶尔得意;这是你的对局,有立场。就眼前局面/对手这步/接某人的话说一句,带你的脾气,别长篇"。

### 3. 自然密度:事件驱动 + 你来我往
- **去掉 ws-server 每 20s 机械 idle 定时器**;改为**沉默驱动的低频补话**:自重排定时器每 ~15s 检查,仅当 ①有进行中的对局(`lastGameId` 且未暂停)②距上一条弹幕已沉默够久(如 ≥30s)③低概率 时,才投一个**贴局面的 idle 刺激**。即"冷场久了才偶尔有人就着棋局补一句",非匀速刷屏。(ws-server 在 emit 闭包里记 `lastChatAt`,定时器据此判沉默。)
- **密度随张力**:`pickSpeakers` 增 `maxSpeakers` 参数,由 chat-engine 按 `stim.tension` 给:高张力(≥0.8)→ 3 人、中(≥0.5)→ 2 人、低 → 1 人。有看头的棋步多几张嘴你来我往,平淡步收声。
- 现有 `TempoGuard`(最短间隔/每分钟上限)保留做总闸;`roundSoFar` 串行注入已实现"同一轮后面的人能看到前面说了啥"的你来我往,配合更大的高张力轮次 + 老黑加入即成对话感。

### 4. 长度:短而有料(收回过度收短)
- `maxTokens` 80 → **70**(够一句有实质的棋评,不啰嗦)。
- 长度档(config `lenShortP`/`lenLongP`)调为 **0.55 / 0.85**(55% 半句/几字、30% 一句话、15% "一句话,可稍长把棋理说透")——多数短,偶尔一句把棋理讲透。恢复实质讲棋,不是短而空。

## 即时生效
- 长度档(lenShortP/lenLongP)是 config 段,控制台可继续调;`maxTokens`、prompt、speaker 概率、idle 逻辑为代码常量(改动需重启/热重载 tsx)。

## 测试策略
- **chat-engine 单测**(沿用现有 capturedUsers/capturedSystems 模式):
  - idle 刺激下 user prompt **含"局面/这盘/棋理"类引导、不含"棋外/家里/行当"**;且引用了缓存的局面上下文。
  - 老黑(player)能在**非 byPlayerPersona** 刺激下作为 speaker 出现(给定 rng),且其 prompt 含"老黑/你的对局/立场"。
  - 高张力刺激(tension≥0.8)选出的 speaker 数比低张力多(验证 maxSpeakers 随张力)。
  - 系统 prompt 含"扣着局面的棋识/别瞎编"与恢复的"把道理说透"。
- **speaker-select 单测**:`pickSpeakers(..., maxSpeakers)` 按上限截断。
- **ws-server**:idle 定时器沉默驱动(可注入短沉默阈值,验证沉默不足时不投、够久才投);既有 WS/暂停集成测试不破。
- 既有 284 server + 32 web 测试不破(改掉 chat-engine 测里关于"棋外/家里"的旧断言)。

## 风险与权衡
- **LLM 跑偏**:prompt 是引导非硬约束,仍可能偶尔离题或贫嘴——靠提示强化"贴局面"+ 去重护栏 + 人工目检。
- **棋识编造**:"带历史掌故/残局"有编造假史风险 → 提示明确"宁可不带也别瞎编",且多数发言不带、只偶尔。
- **老黑话太多**:中等概率 + TempoGuard 总闸控制;若仍多,降低参与概率(易调)。
- **密度主观**:事件驱动 + 张力分级是结构性改善;具体阈值(沉默 30s、张力 0.8/0.5、概率 0.6/0.3)为初值,可后续微调/上控制台。
