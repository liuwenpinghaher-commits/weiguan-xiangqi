## P0 — 正确性硬伤 / 招牌功能对最常见场景失效

1. **【bug】将死/困毙结局的对局永远无法诊断，且自动路径静默吞错**
   `diagnose-game.ts:49-58` 对每个局面（含终局 FEN）逐一 `analyze`。真实 Pikafish 实测：将死局面返回 `info depth 0 score mate 0`（**无 pv 字段**）+ `bestmove (none)`，`parseInfoLine` 因无 pv 返回 null（`uci-parse.ts:9-10`）→ lines 为空 → `diagnose-game.ts:57` 抛"引擎分析返回空"→ 整局零标注、零 ACPL/Elo。自动诊断在 `ws-server.ts:448` 被 `.catch(()=>{})` 静默吞掉；手动 `POST /games/:id/diagnose` 同样失败且错报 404（`ws-server.ts:564-574`）。
   **后果**：将死取胜/被将死这类最常见的决胜结局，成长飞轮完全失效，用户毫无感知，每次尝试还白烧一整局 depth12 引擎分析。`diagnose-game.test.ts` 全用 fake 引擎恒返回行——测试假绿。
   **修法方向**：诊断循环跳过（或特判）终局 FEN；`bestmove (none)`/无 pv 时以 mate 分补一条零 pv 的 EngineLine 而非抛错。

## P1 — 并发竞态 / 招牌功能触发不到

2. **【bug】同一局并发走子竞态，写坏棋谱**
   WS message handler 是 `async` 且无 per-game 串行化（`ws-server.ts:378,431-437`）；`playHumanMove` 的完局/轮次/合法性守卫全在 `await engine.analyze` 之前（`game-session.ts:275-291`），await 后仅复查 `isFinished`（:344-346），不复查局面是否已被并发推进。AI 思考窗口（movetime 数百 ms~5s）内到达第二手 move（双击、双标签页），两次都通过守卫、各写一对人着+AI 着（:355-357）→ moves 表红黑交替断裂、fenAfter 断链，DB 棋谱永久污染，复盘/诊断/训练跟着错。

3. **【bug】undo 与 AI 思考在途并发 → DB 着法序列损坏、对局永久打不开**
   `ws-server.ts:435` `await playHumanMove` 期间，`undo` 帧（:522-525）同步执行 `deleteLastMove`×2+重建；analyze 返回后 `game-session.ts:355-357` 把基于**悔棋前局面**算出的着法追加进已回退的 DB。此后任何 `rebuildDerivedState`（续局/再悔棋）重放到该手 `applyMove` 非法 → 抛错，**该局永久打不开**。前端悔棋按钮在"AI 思考中"未禁用（`web/src/pages/PlayPage.tsx:423` 仅按 undoRemaining），服务端无 per-game 互斥。

4. **【bug】aiFirstMove / resign / offerDraw 缺完局守卫，已定结果可被覆写**
   `playHumanMove` 有"analyze 后二次完局守卫"（`game-session.ts:344-346`），但同款没推广到旁路：
   - `aiFirstMove`（:461-501）await 期间若已 finish，会向已有 result 的对局追加脏 by_ai 着法、复活内存态、`repeatHistories.get(gameId)!` undefined → TypeError。触发：执黑开局，`started` 帧先于 `await aiFirstMove`（`ws-server.ts:411-425`），玩家在 AI 首手思考窗口内点认输/求和。
   - `resign`（:659-669）/`offerDraw`（:671-695）均不查 `isFinished`，`finishGame` 无条件 `UPDATE games SET result`（`games-repo.ts:50-52`）→ 已赢（将死）的局，终局后再到达一条 resign/draw 帧，result 被改写为判负/和，污染导演 winStreak 与成长统计。触发：终局后重复点击、消息重放、多标签页。

5. **【开环】turning_point / phase_shift 深度点评被 TempoGuard 静默吞掉**（招牌功能）
   同一手连发最多 4 条刺激（`game-session.ts:396-432`）；ChatEngine 里只有 coach_query 免闸（`chat-engine.ts:121`），任一前序刺激发言即 `record()` 刷新 lastAt（:148-149），后续刺激在 ~1.5-3s 内到达，撞 `minSilenceMs=4000`（`defaults.ts:23`、`tempo.ts:14-17`）→ 直接丢弃。人着吃子（张力 0.9 几乎必发言）或转折手的 AI 刺激为 blunder/brilliant（0.95 必中）——只要一个说了话，紧随的 turning_point 必被吞。两条 LLM 调用合计不足 4s，无自然逃逸窗。`595a580` 声称的"关键刺激免静默"只绕过了最近发言惩罚、没绕 TempoGuard，且单测全用 `minSilenceMs:0` 绕闸（`chat-engine.test.ts:646`）= 假绿。

6. **【开环】前端 `dropQueued` 无差别清队，可静默砍掉教练必答的语音回答**（招牌功能）
   `dropQueued()` 直接 `queue = []`（`web/src/voice/server-tts.ts:174-176`），不区分 coach/human。玩家提问 → 教练回答已合成入队但前面有一句在播 → 玩家随即走子 → `handleMove` 调 `dropQueued()`（`PlayPage.tsx:274`）→ **教练语音回答永不播放**。服务端 `chat-engine.ts:96`"coach_query 一律不丢"的必答承诺在最后一环（前端队列）破功；设计文档只防了"旧弹幕给回答让路"，没防"走子给回答砍队"。

7. **【bug】超时清扫广播的 update 帧缺 gameId，旧局 flag-fall 杀死当前新局 UI**
   清扫帧 `{type:'update',aiMove:null,...timedOut,clockState:null}` 广播给所有 socket（`ws-server.ts:255-267`），而 `checkTimeout` 返回值不含 gameId（`game-session.ts:151-152`）；前端 chat/undo/draw 都按 gameId 过滤，唯独 update 无 gameId 可滤，直接 setFen+判终局（`PlayPage.tsx:85-130`）。旧局未认输就点"新对局"（前端只发 new 不 resign），旧局走钟在服务端内存继续走、归零 → 广播 → **正下着的新局棋盘被替换成旧局终局面并弹胜负**。

8. **【bug/资源】终局后 idle 弹幕永不停机，空烧 LLM token**
   `lastGameId` 只在开新局赋值（`ws-server.ts:407`），`cleanupFinishedGame` 不清它（:293-297）；idle 判定只看 `lastGameId !== null` 与 paused（:237-245），而 paused 容器终局时恰被删 → 恒 false。一局结束（含关页离开）后不再开新局，则每 idleInterval 掷中 idleProb 就对已结束的局投 idle 刺激（每条 1-2 次 LLM + 落库），永续运行；`forgetGame` 已清 lastCtx，prompt 退化为"这局还在走"（`chat-engine.ts:311`）——对一盘已结束的棋无限闲聊。

9. **【bug】点"开始对局"不清旧弹幕不停旧语音，新局重播上一局旧内容**
   `handleStart`（`PlayPage.tsx:233-245`）与 `handleRestart`（:283-306）不对称，缺 `setLines([])`/`stopVoice()`/`cancelSpeech()`。上一局结束（lines 存满旧弹幕）→ 点"▶ 开始对局"→ 新 gameId 使 `ChatPanel key={gameId}` remount → `revealedCount` 归零 → useEffect 从 0 重扫旧 lines 逐条 speakServer → **重播旧局最后几条语音**并把旧弹幕串台显示进新局；上一局收官点评若在播也无人停。

10. **【bug】断连自愈只自愈连接、不自愈状态，`update`/`started` 帧丢失即死锁**
    重连成功仅恢复文案（`PlayPage.tsx:190-194`），协议无任何状态重同步消息。走子后 AI 回帧在途时断线（awaitingAi=true）→ 棋盘永久锁死（`disabled=awaitingAi` :510，无解锁路径）；`new` 发出后 `started` 在途断线 → gameId 恒 null 永停"正在创建对局"。上轮修好的是"连接层"退避重连，"状态层"未闭环。

13. **【bug】mate 裸分（±30000）落库并注入 narrative prompt**

14. **【风险】嵌入换 bge-m3 后相似度阈值未重标定，L1 地板双向失真**
    `sqlite-memory-store.ts:9-13` 的 judge 阈 0.6 与地板 0.3 是按 DashScope text-embedding-v3 标定的，生产已是 Ollama bge-m3。本机实测 bge-m3：完全无关对 cos=0.465（>0.3 照样注入 prompt）、同域相关对 cos=0.286（<0.3 被滤掉）、"相关不同事实"对 cos=0.631（>0.6 每次写入多打一次 LLM judge）。地板防低相关注入的本意失效。修法：按 bge-m3 重跑 `scripts/calibrate-sim-threshold.ts` 调默认值。

15. **【运维】`.env.example` 与现架构脱节，照抄部署会静默丢语义检索**
    未记载 `EMBEDDING_BASE_URL`/`EMBEDDING_API_KEY`（`ws-server.ts:107-108` 的解耦开关），注释仍称嵌入走 text-embedding-v3、失败"降级内存不持久模式"（SQLite 后已不存在）。照抄 example + chat 配 DeepSeek → 嵌入回退 llm 段打 DeepSeek `/embeddings` 404 → 语义检索静默退化为 recency 召回，仅 `/admin/memory` degraded 字段可见。

16. **【风险】`/play` WS 无 Origin 校验（CSWSH）**
    `fastifyWebsocket` 注册无 verifyClient（`ws-server.ts:344,355`）。浏览器 WebSocket 不受 CORS 约束——用户浏览器中任意网页可连 `ws://127.0.0.1:3410/play`：建局、灌 say（每条触发引擎分析+LLM 生成+落库，烧 token）、窃听全部 chat/update 广播。HTTP CORS 与 /admin 的 loopback 闸都挡不住（浏览器发起的本机 WS 源 IP 即 127.0.0.1）。附带 `GET /tts?text=` 跨站可白烧 TTS 费；WS 帧未设 maxPayload（默认 100MiB）。【未用恶意页面实测】

17. **【静默吞错】coach_query"必答"在异常路径静默失守**
    单 speaker 失败仅 warn（`chat-engine.ts:211-215`）；stripStageDirections 清空整句则 continue（:167-168）；与教练上一句逐字相同被去重丢弃（:171-174，测试自认风险）；外层 insight/生成失败整体静默（`ws-server.ts:482`）。玩家提问有回显但永无回答，前端无任何失败态或降级话术。

18. **【静默吞错】有 apiKey 无 baseURL 时静默落 FakeLLM，零日志**
    `buildInnerLlm`（`mutable-llm.ts:23-27`）在 apiKey 存在但 baseURL 缺失时返回 `FakeLLM`（chat 全空串）；启动警告只检查 apiKey（`ws-server.ts:97`），该场景一条日志都没有，聊天/反思/成长报告全静默无输出。反向误报：本地 Ollama（无需 key）时该警告错误宣称"聊天功能不可用"。

19. **【开环】嵌入故障期写入的 fact/insight 永久"二等公民"，无回填**
    Ollama 掉线时 `record()` 降级插 embedding=NULL（`sqlite-memory-store.ts:81-82`），恢复后健康态检索 sim=0 被 0.3 地板滤掉（:143-144）永不注入，NN 去重也只查 `embedding IS NOT NULL`（:86）不参与。无补嵌入任务。附带 bug：控制台编辑记忆时重嵌入失败会无条件写 NULL 清掉旧向量（:174-177），与 merge 路径"失败保留旧向量"策略自相矛盾。

20. **【开环】中途关页反思"抢跑"后，终局反思被幂等闸吞掉**
    socket close 时 ≥6 人类着即 `reflectGame`（`ws-server.ts:360-376`）并进 `reflectedGames`（:176）；用户重开页续完此局后，move-over 反思因幂等提前 return（:172）→ 含最终胜负与后半盘的完整反思永不发生，记忆只沉淀到关页那一刻。双标签页关一个也会对进行中的局抢跑。附：`doReflectGame` 只取 `humanMoves.slice(0,12)`（:191），长局中残局着法进不了反思素材。

21. **【开环/缺失】自动诊断只挂 move-over 路径 + 无终局播报刺激**
    认输、超时判负（清扫器）、求和成立三种终局都不触发自动诊断（`ws-server.ts:439-452` 仅 move-over）；与 P0-1 叠加后，自动产出成长指标的结局实际只剩"三次重复/60 回合和棋"和"走子入口内超时判负"。且 StimulusKind 无 game_end 类（`types.ts:113-116`），将死取胜时茶馆对"绝杀/胜负"这一最高潮无专门反应，终局刺激还被 `cleanupFinishedGame` 随即清掉上下文。

22. **【bug】时钟结算先于走子校验，非法走子可无限冻结/续时**
    `game-session.ts:279-280` `settleActive`（结算+加增秒默认 5s）在 not-your-turn（:288）与 illegal（:291）守卫之前。非法/非轮次走子到达 → 抛错但时钟已被结算冻结（activeSide=null，清扫器对该局失效）且走子方白得增秒，可重复蹭时。拖拽路径与自定义客户端可达。

23. **【风险】引擎子进程崩溃后无重生、无降级标记**
    `ws-server.ts:70-73` 仅启动 spawn 一次；崩溃后每次 `analyze` 向死 transport 写（safeWrite no-op），等满 movetime+2000ms 才超时报错。引擎一旦崩溃，所有对弈/诊断每手先卡 ~2.5s 再报错直到人工重启；无 respawn、前端无"引擎不可用"状态。

24. **【资源泄漏】终局后 `ensureLoaded` 复活内存态且永不回收**
    `game-session.ts:162-182` 不检查 `g.result`；终局后玩家一句提问（say→getFen）即重建 positions/modes/humanSides/repeatHistories/noCapturePlies 并永久驻留，`finish` 已执行过、无路径再清理。每盘"局后提问过"的对局泄漏一整套局面态。附：`pausedGames`/`spectatorsOffGames` 只验 `typeof gid==='number'` 不验局存在（`ws-server.ts:485-501`），任意 gid 可无限膨胀。
