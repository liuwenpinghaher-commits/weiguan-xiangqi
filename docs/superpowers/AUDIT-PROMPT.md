# 围观象棋 · 全系统审计 Prompt（可复用）

> 用法：每轮全系统审查直接按本文档执行。审查产出写入 `docs/superpowers/AUDIT-YYYY-MM-DD.md`。
> 本文件是对历轮审查方法的沉淀与完善（首轮 2026-06-20，二轮/三轮 2026-07-03），
> 吸收了三轮审查 + 后续修复中反复出现的缺陷类型。

## 一、目标

对整个系统做**架构完整性 / 功能完善度 / 业务闭环**三维深挖，回答一个问题：
**"设计文档承诺的体验，用户今天真的能走到吗？走到的路上会不会被坑？"**

审查只找问题、不改代码（只读）。修复由用户另行指令。

## 二、审查基准（对照物）

1. 主设计：`docs/superpowers/specs/2026-06-19-围观象棋-design.md`（承诺 vs 实现）
2. 后续增量设计/计划：`docs/superpowers/specs/` 与 `docs/superpowers/plans/` 下所有日期 ≥ 上轮审计的文件
3. 上轮审计报告与修复承诺：最近一份 `AUDIT-*.md` + 其后的修复提交（回归检查：修复是否真的生效、有没有修出新问题）
4. 上轮审计后的全部新提交（`git log <上轮修复提交>..HEAD`）——**新代码是本轮重点**

## 三、方法（刚性要求）

- **并行只读审查者**，按第五节的 7 个维度各派 1 人，互不重叠处写明"移交给维度 X"。
- **证据强制 `文件:行`**。没有代码证据的发现一律标 `【未验证】`，不许伪装成事实。
- **每个发现给复现路径或触发条件**（什么输入/什么状态 → 什么错误表现），不接受"感觉不对"。
- **区分缺陷类型**：`bug`（行为错）/ `死码`（写了走不到）/ `开环`（做了一半不闭环）/ `死值`（配置定义了但没接线或没持久化）/ `缺失`（承诺没做且未声明）/ `风险`（依赖未验证假设）/ `运维` / `弱`。
- **分级**：P0 = 正确性硬伤、数据污染、崩溃/卡死；P1 = 招牌功能死码或开环；P2 = 数据/运维不闭环;P3 = 产品化欠账。
- **审查后必须复核**：P0/P1 发现须由汇总者对照真实代码逐条验证后才能进报告；验证不过的降级或删除。
- **回归优先**：每个维度先检查"上轮在本维度修的问题是否真的修好"，再挖新问题。

## 四、历轮反复出现的缺陷类型（本轮必查清单）

以下 10 类在前三轮审查/修复中反复出现，每个审查者在自己维度内**逐条对照**：

1. **视角转换错**：引擎 cp 是"走子方视角"，展示/叙事/记忆是"红方视角"，每一处转换桥都要有测试且方向正确（历史案例：`redCp = aiSide==='red'?aiCp:-aiCp` 零测试；buildNarrative 曾漏转换）。
2. **mate/极值污染统计**：杀棋分（±3万）流入均值类统计（ACPL/Elo/swing 检测）会爆表；所有聚合点检查是否钳制或剔除。
3. **配置死值**：字段有默认值、有校验、有控制台 UI，但**运行时没接线**或**DB 不持久化**（案例：coachQueryTension 不入库、humanlike 模式前端写死不可达）。三查：定义 → 接线 → 持久化。
4. **限流/静默把关键消息吞掉**：tempo/去重/让路逻辑是否会静默教练必答（coach_query）、将杀提示、胜负播报（案例：关键刺激曾被限流闸吞掉）。
5. **队列滞后与丢弃策略**：TTS/弹幕队列"丢旧保新"是否误丢必达消息；快速走子时点评是否还在说 N 步前的局面。
6. **资源泄漏**：引擎子进程、定时器、WS 连接、音频上下文——每条创建路径都要有对应销毁路径（含异常路径、会话结束、断连）。
7. **接线层无测试**：`ws-server.ts` 是全系统唯一组装点，纯逻辑测试全绿 ≠ 接线正确;检查每个 handler 的错误分支与状态机。
8. **静默吞错**：`catch` 后不上报不降级只 console（或连 console 都没有），前端拿不到失败态（案例：TTS 无声静默失败、GrowthPage 吞错）。
9. **prompt 与行为不符**：LLM prompt 里承诺的行为（引经据典、字数、单人发言、教练必答）与代码限流/裁剪逻辑是否互相打架。
10. **凭据与环境变量串用**：多 provider（DeepSeek / DashScope / Ollama）的 key、endpoint、model 名是否隔离清晰;缺 key 时能否降级启动而不是崩（案例：ASR 凭据曾串入 chat 模型;缺 ARK key 全系统起不来）。

## 五、审查维度与范围（7 名并行审查者）

| # | 维度 | 范围 | 特别盯 |
|---|---|---|---|
| 1 | 规则/引擎/对弈会话 | `server/src/rules` `engine` `session` `director` `analysis` | 长将长捉/重复局面判定、视角桥、cploss/insight 聚合、undo/clock、引擎超时与崩溃兜底 |
| 2 | 聊天/叙事/点评 | `server/src/chat` `personas` | 张力/阈值实际可达性（idle 0.7 vs threshold）、单人发言与教练必答的冲突、narrative 红方视角、引经据典是否落到 prompt、去重误伤 |
| 3 | 语音双向 | `server/src/voice` `web/src/voice` | ASR/TTS 凭据隔离、丢旧保新误丢、coach_query 让路链路、降级与错误提示、音频资源释放 |
| 4 | 记忆/存储 | `server/src/memory` `store` | SurrealDB→SQLite 迁移残留、嵌入检索地板值、supersede、事务与 WAL、记忆写入触发点是否覆盖所有局终形态 |
| 5 | LLM/配置/控制台 | `server/src/llm` `config` `admin` `report` | provider 切换一致性、超时/重试、配置三查（定义→接线→持久化）、控制台字段与后端 schema 对齐 |
| 6 | 前端 | `web/src`（pages/board/chat/api/ui/hooks/main） | WS 断连重连、状态机竞态、麦克风默认入口的权限失败路径、响应式/无障碍回归、api 层与后端契约 |
| 7 | 跨切面接线/运维/安全 | `ws-server.ts` `index.ts` `types.ts` 全局 | 组装点每 handler 的错误分支、资源生命周期、并发竞态、优雅关闭、secrets 不落日志、依赖注入完整性、测试假绿（mock 覆盖但接线无测试） |

## 六、每名审查者的输出格式

```markdown
### 回归检查（上轮修复复核）
- [R] <上轮问题> → 现状（已修好 / 复发 / 修出新问题），证据 `文件:行`

### 新发现
- **【类型·P级】标题**：现象 + 触发条件 + 后果。证据 `文件:行`。
```

## 七、汇总报告结构（AUDIT-YYYY-MM-DD.md）

1. 日期 / 方法 / 基线（测试与构建通过情况，先跑 `npm -w server test` 与 web typecheck 记录真实结果）
2. 总评表（架构 / 测试 / 闭环 / 产品化 / 诚实度，各一句话评价）
3. 一句话总评："今天用户实际能得到什么体验"
4. P0 → P3 分节列发现（经复核的才进；每条带证据与触发条件）
5. 回归检查汇总（上轮修复的存活情况）
6. 明确声明"本轮未覆盖什么"（诚实度：不许假装全覆盖）
