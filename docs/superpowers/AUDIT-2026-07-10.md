## P1

### 1. 成长页切换红黑方时，棋力曲线和成长点评仍是全量数据

**证据**

- `web/src/pages/GrowthPage.tsx:41-63` 中 side 变化后同时拉取 `getGrowth()`、`getWeakness(side)`、`getCompare()`，只有弱点画像带了 side。
- `web/src/api/http-client.ts:33-36` 中 `getGrowth` 和 `getCompare` 没有 side 参数。
- `web/src/pages/GrowthPage.tsx:93-95` 标题会显示“红方/黑方”，但下方 `metrics` 和 `cmp` 不是该方数据。
- `server/src/ws-server.ts:803-812` 的 `/compare` 已支持 `?side=red|black`，但前端没传。
- `server/src/ws-server.ts:742-743` 的 `/growth` 当前没有读取 side，虽然 `server/src/store/analysis-repo.ts:46-52` 的 `listGrowthMetrics(side?)` 已具备按方过滤能力。

**影响**

用户切到黑方时，以为看到的是“黑方成长轨迹”和“黑方成长点评”，实际看到的是红黑混合数据。这会直接误导成长判断和训练方向，属于核心成长飞轮的语义错误。

**建议修复**

让 `getGrowth(side)`、`getCompare(side)` 统一带上 side；后端 `/growth` 透传 query 到 `listGrowthMetrics(side)`；补前端状态测试和后端接口测试，覆盖红黑混合样本。

### 2. 对局页终局提示没有消费真实 `diagnosisStatus`

**证据**

- `web/src/pages/PlayPage.tsx:527-535` 在终局区调用的是 `postGameAnalysisHint()`，没有传入诊断状态。
- `web/src/pages/play-state.ts:34-40` 的 helper 已经支持 `ok`、`failed`、`running`、`pending`，但 PlayPage 未接入。
- `server/src/ws-server.ts:733-740` 的 `GET /games/:id/diagnosis` 已返回 `diagnosisStatus`。
- `web/src/pages/AnalysisPage.tsx:19-33` 已能展示失败、运行中、待诊断状态，说明能力只接到了分析页，没有接到对局页局后入口。

**影响**

自动诊断失败或仍在运行时，对局页局后提示仍是泛化文案。用户只有点进分析页才知道真实状态，局后闭环的入口仍存在“看起来完成，实际未完成”的问题。

**建议修复**

PlayPage 在终局后拉取 `/games/:id/diagnosis`，保存 `diagnosisStatus` 并传给 `postGameAnalysisHint(status)`；或者让服务端终局/update 帧携带诊断状态。补 `play-state` 和 PlayPage 组件级测试。

## P2

### 4. `diagnosisStatus` 只存在内存，服务重启后失败状态会丢失

**证据**

- `server/src/ws-server.ts:328-348` 使用进程内 `diagnosisStates` Map 记录 `pending/running/ok/failed`。
- `server/src/ws-server.ts:398-415` 的自动诊断只更新该 Map。
- 当前没有对应的 DB 字段或表持久化诊断状态。

**影响**

自动诊断失败后，如果服务重启，失败状态会退回到 `pending` 或按已有 annotations 推断为 `ok`。用户和维护者会丢失“曾经失败”的排障线索，诊断状态的可观察性只在当前进程内成立。

**建议修复**

新增轻量持久化，例如 `game_diagnosis_status` 表或 `games.diagnosis_status/diagnosis_error` 字段；自动诊断和手动诊断都写入；`GET /games/:id/diagnosis` 先读持久状态，再结合 annotations 推断。

### 5. 对局页引擎状态只在加载时读取一次

**证据**

- `web/src/pages/PlayPage.tsx:254-258` 只在组件加载时 fetch `/engine/status`。
- `server/src/engine/managed-engine.ts:22-45` 已暴露 degraded/error 状态，并在失败后重建重试。

**影响**

如果引擎在页面打开后变为 degraded，对局页状态卡不会主动更新。用户可能只在下一次走子、诊断或分析报错时才意识到引擎异常。

**建议修复**

在引擎相关错误后刷新 `/engine/status`；或者低频轮询并带退避。不要高频轮询，避免本地桌面应用无意义开销。

### 6. `/weakness` 的 side query 没有显式校验

**证据**

- `server/src/ws-server.ts:745-749` 将 `req.query.side` 直接 cast 为 `'red' | 'black' | undefined`。

**影响**

`/weakness?side=foo` 不会返回 400，而是进入仓库查询并得到空画像。这是轻量 API 诚实度问题，不影响正常 UI，但会增加调试歧义。

**建议修复**

复用 `/compare` 的 side 校验逻辑，非法 side 返回 400，并补一条接口测试。
